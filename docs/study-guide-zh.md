## 从头读一次

1. 在 `BreathingCity.pde` 看 `setup()`：初始化画面、输入、效果和调试信息。再看 `draw()`，确定每一帧怎样选择真实麦克风、鼠标或自动演示输入。
2. 在 `BreathInput.pde` 看 `begin()`：先选设备，`AudioIn(parent, 0)` 的 `0` 是设备的第 0 个声道，不是设备编号。`start()` 只采集，不把麦克风声音播放到扬声器。`Amplitude` 把一个音频块算成 RMS 数值。
3. 在 `SignalEnvelope.java` 追踪 `raw → noiseFloor/gate → target → intensity`。只有平滑后的强度被用来控制画面。
4. 在 `CityScene.pde` 追踪 `energy`。它影响颜色、窗户、地标灯光、水面振幅和相位变化速度。
5. 在 `VisualEffects.pde` 看触发条件、生成速率、对象寿命和逆序删除。这部分解释为什么对象不会无限积累。

## 声音怎样变成数字

麦克风送来正负变化的采样波形。`Amplitude.analyze()` 返回一段音频的均方根：先平方、再取平均、再开方。它表示声音强度的相对数值，没有识别“这是不是呼吸”。说话、拍手、音乐、风扇都可能触发。

程序没有记录或上传原始音频。屏幕数值也不是专业声压计的 dB SPL；设备增益、距离、系统降噪都会影响它。

## 校准、阈值与平滑怎样配合

- **校准**：保持安静，收集约 3 秒样本，取第 90 百分位作为环境底噪。至少 45 个样本，最多存 720 个。持续讲话会抬高估计，应重新校准。
- **门限**：打开值 = 底噪 + `margin`；关闭值 = 底噪 + `0.55 × margin`。上下两条线避免门状态在单一边界附近来回切换。
- **灵敏度**：`target = clamp((raw - openingThreshold) × sensitivity / 0.06, 0, 1)`。增大灵敏度只扩大超出门限的信号，不改变麦克风硬件增益。
- **平滑**：`alpha = 1 - exp(-dt / tau)`；新值 = 旧值 + `alpha × (target - 旧值)`。升起 `tau=0.10 秒`，下降 `tau=0.55 秒`。`tau` 是时间常数，不是到达最终值所需的全部时间。
- **时间**：`dt` 是秒数，因此正常情况下换一台帧率不同的电脑不会把“0.55 秒的回落”变成固定帧数。卡住很久时程序限制一次步进，防止突然跳动。

举例：底噪 `0.003`、margin `0.002`、灵敏度 `1`，则打开门限为 `0.005`。raw=`0.017` 对应 target=`0.20`，raw=`0.059` 对应 target=`0.90`。这是公式演示，不代表任何人的真实轻/强呼吸。

## 为什么强输入明显不同

| 变化 | 轻输入 | 强输入 | 主要代码 |
|---|---|---|---|
| 天空与灯光 | 暗、冷色 | 更暖、更亮、更多窗户亮起 | `drawSky()`、`CityBuilding.display()`、地标绘制 |
| 海浪 | 振幅小，相位推进慢 | 振幅大，推进快 | `CityScene.display()`、`drawHarbour()` |
| 粒子 | 每秒生成少，上升慢 | 生成快，上升快 | `VisualEffects.updateAndDraw()`、`BreathParticle` |
| 波纹 | 较细、扩散慢 | 更粗、更亮、扩散快；持续强输入可重复 | `BreathWave` 和峰值追踪 |

波纹不是“能量大于门限就每帧生成”。开始事件用 `>0.12`，重新准备下一事件用 `<0.06`，还有限制时间间隔。产生波纹后继续更新峰值，避免强输入刚跨门限时就被永久记成弱波纹。

## 调参顺序

先用 `N` 选正确输入设备，必要时 `I` 重连；按 `R` 安静校准。背景噪音误触发时用 `]` 提高 margin；轻呼吸太难触发时可用 `[` 降一点。已经超过门限但视觉太弱时用 `=` 提高灵敏度，太容易满格时用 `-` 降低。`0` 恢复默认 margin 和灵敏度。每次只改一种参数并记下前后数值。

`G` 开始 60 秒引导麦克风测试：0–10 秒安静（含校准）、10–25 秒轻输入、25–40 秒强输入、40–55 秒停止、55–60 秒结束。阶段标签只是提示，需要参与者确认实际做了什么，再把数据当作相应测试结果。

`M` 是鼠标模拟，`A` 是自动演示。鼠标位置直接映射到平滑后的强度，会绕过校准、门限和灵敏度，因此这些调参不会改变鼠标响应。自动演示则通过真实的 `SignalEnvelope` 处理模拟 RMS。它们适合检查视觉和代码路径，但不能替代麦克风测试。`D/H` 控制数据/帮助面板，`S` 保存截图。最终完整快捷键以 README 和屏幕帮助为准。

## 用自己的话复习

运行前先预测：把灵敏度翻倍会发生什么？把 release 从 0.55 改成 1.1 会怎样？停止输入后粒子会立刻消失吗？在鼠标模式能否证明麦克风正常？为什么 amplitude 不能区分吹气和说话？

完成一次真实实验后，把预测、实际结果、代码改动和解释写进 [项目日志](project-journal.md)。不要把这份 AI 生成的讲解当作已经发生的个人学习经历。
